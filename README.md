## 📖 Description

FellahConnect is a **Node.js / Express / Sequelize (PostgreSQL) REST API** for a Moroccan AgriTech platform. Based on the model definitions and business logic present in the code, the domain covers:

- **Farmers (`Agriculteur`)** linked to a user account.
- **Land parcels (`Parcelle`)** owned by a farmer.
- **Harvests (`Recolte`)** produced on a parcel, of a given product.
- **Products (`Produit`)** (e.g. measured in `kg`, `tonne`, `litre`).
- **Markets (`Marche`)** where products are sold.
- **Market prices (`PrixMarche`)** of a product at a market, over time.
- **Sale offers (`Offre`)** created from a harvest and proposed at a market.

The repository also contains the beginnings of an **AI assistant** (`src/ai`, `src/tools`, `src/services/agent.service.js`) intended to let farmers query prices, harvests, and parcels, and create/update/delete records through a conversational interface backed by the OpenAI SDK, using a tool-calling ("function calling") pattern.

## 🏗 Architecture Overview

The project follows a layered **MVC-inspired** structure (routes → controllers → services → models), common for Express + Sequelize APIs:

```
Client
  │
  ▼
Express App (src/server.js)
  │  app.use(express.json())
  │  app.use('/api', allRouter)
  ▼
Routes (src/routes/*)         — define URL paths and HTTP verbs, map to controllers
  ▼
Controllers (src/controllers/*) — parse req/res, call services, format HTTP responses
  ▼
Services (src/services/*)     — business logic, call Sequelize models
  ▼
Models (src/models/*)         — Sequelize model definitions mapped to PostgreSQL tables
  ▼
PostgreSQL (via docker-compose.yml)
```

Additional cross-cutting pieces:

- **`src/middlewares`** — authentication (`autorize.middleware.js`), authorization/RBAC (`authorize.middleware.js`), and request validation (`validation.middleware.js`). `Needs manual confirmation`: none of these middlewares are currently wired into any route file.
- **`src/ai` / `src/tools`** — a separate "agent" subsystem: `agent.routes.js` → `agent.controller.js` → `agent.service.js` (calls the OpenAI SDK) → `toolsFunctions.js` (executes reads/writes against the Sequelize models on the AI's behalf).
- **`src/config/database.js`** — single Sequelize instance shared across all models, configured from environment variables.
- **`sequelize.config.js`** — present at the project root (0 bytes / empty) — intended for Sequelize CLI configuration (migrations/seeders), but currently has no content.

## 🔐 Authentication

- **Registration** (`UserServies.regester` in `src/services/user.service.js`): checks for existing `username`/`email`, hashes the password with `bcrypt` (`src/utils/bcrypt.js`), and creates a `User` row with `role` (`admin` or `agriculteur`).
- **Login** (`UserServies.login`): looks up a user by `username` or `email`, compares the password hash with `bcrypt`, and on success calls `ganerateToken()` (`src/utils/jwt.js`) to issue an **access token** (1 hour expiry, signed with `ACESS_TOKEN_SECRYT_KEY`) and a **refresh token** (7 day expiry, signed with `REFREASH_TOKEN`).
- **Request authentication** middleware (`src/middlewares/autorize.middleware.js`, function `authenticate`): reads the `Authorization` header, expects a `Bearer <token>` format, and verifies it with `jsonwebtoken` against `ACESS_TOKEN_SECRYT_KEY`.
- **Authorization / RBAC** middleware (`src/middlewares/authorize.middleware.js`, function `authorize(...roles)`): expects the calling user's data at `req.body.user`, loads the `User` record, and rejects the request with `403` if the user's `role` is not in the allowed list.

`Needs manual confirmation` / ⚠️ As inspected, **none of the route files apply `authenticate` or `authorize` to any endpoint** — every route currently defined is unauthenticated at the routing layer. See [🐞 Known Issues](#-known-issues).

## ❗ Troubleshooting

| Symptom | Cause (from source inspection) |
|---|---|
| Server fails to start with a "Cannot find module" error for `./auth.routes.js` | `src/routes/index.js` imports `auth.routes.js`, which does not exist anywhere in the repository. |
| Server fails to start with a "Cannot find module 'express'" error even after `npm install` | `express` is used throughout `src/` but is **not listed** in `package.json` dependencies or `package-lock.json`. Run `npm install express`. |
| `validation.middleware.js` throws a module-resolution error for `zod` | `zod` is imported in `src/middlewares/validation.middleware.js` but is **not listed** in `package.json` dependencies (though it does appear in `package-lock.json`, implying it was installed at some point without being saved to `package.json`). Run `npm install zod`. |
| `src/utils/bcrypt.js` throws a syntax error on import | The file contains `import bcrypt from bcrypt;` — the module specifier is missing quotes around `bcrypt`, which is invalid JavaScript syntax. |
| `src/models/index.js` throws a module-resolution error for `./OffreVente.js` | It imports the offer model as `OffreVente.js`, a filename that does not exist in `src/models/` (only `Offre.js` exists). |
| `src/services/market.service.js` throws a module-resolution error | It imports `"../models/Marche.js "` — note the trailing space in the string, which does not match the actual file `Marche.js`. |
| `src/models/Recolte.js` throws `DataTypes is not defined` | The file uses `DataTypes.INTEGER` / `DataTypes.FLOAT` / `DataTypes.DATE` but never imports `DataTypes` from `sequelize` (unlike the other model files). |
| `src/models/Offre.js`, `Parcelle.js`, `Produit.js`, `Recolte.js` may fail to resolve the database config | They import `"../config/database"` without the `.js` extension, while the actual file is `database.js`; Node's ESM resolver generally requires explicit extensions for relative imports. |
| `GET /api/.../:id` on any resource returns unexpected results or throws | Each controller's `getById` reads params inconsistently (some read `res.params.id` instead of `req.params.id`) and calls the service **without `await`**, so the `if(!data)` check runs against a pending `Promise` (always truthy) rather than the resolved value. |
| `POST /api/agriculteurs`, `/api/parcelles`, `/api/produits`, `/api/recoltes`, `/api/marches`, `/api/prix-marche` return 500 "server error" | Each of these controllers' `setData` calls a **generic** method name (e.g. `AgriculteurServers.addProduit`, `ParcelleServes.addProduit`) that does not exist on the corresponding service class — the actual service methods are named per-entity (e.g. `addAgriculteur`, `addParcelle`). The same mismatch appears across `getAll` (`selectProdiutAll` vs. e.g. `selectAgriculteurAll`), `getById` (`getProduitById` vs. e.g. `getAgriculteurById`), `delete` (`deleteProduitById` vs. e.g. `deleteAgriculteurById`), and `update` (`updateProduitById` vs. e.g. `updateAgriculteurById`) for every resource **except** `Produit` itself, whose service method names do match its controller. |
| `POST /api/offres` always fails to persist data | `OffreControle.setData` calls `OffreVenteServies.addProduit()` without forwarding `req.body`, so no data would be saved even if the method name matched. |
| `POST /api/agent/chatBot` throws on every call | `src/services/agent.service.js` calls `OpenAI({...})` without `new`, uses non-existent option/parameter names (`APIKey` instead of `apiKey`, `module` instead of `model`, `message` instead of `messages`), and references an undeclared `toolFunctions` variable (the actual export from `src/tools/toolsFunctions.js` is never imported into this file). |
| The AI agent's system prompt is `undefined` when imported | `src/ai/systemPrompt.js` defines the `systemPrompt` constant but never `export`s it, while `agent.service.js` does `import systemPrompt from "../ai/systemPrompt.js"`. |
| `POST /api/auth/login` / `.../register` cannot be reached | The controller and route logic exist (`user.controller.js`, `user.routes.js`), but `user.routes.js` is never imported/mounted by `src/routes/index.js` (which instead imports the missing `auth.routes.js`). |
| Login always fails with a token-generation error | `UserServies.login` calls `ganerateToken()` with no arguments, but `ganerateToken` (in `src/utils/jwt.js`) expects a `userData` object and immediately accesses `userData.id`. |
| `autorize.middleware.js`'s `authenticate` function throws on a missing token instead of returning a clean 401 | It calls `res.status(401).json(...)` when the token is missing but does not `return`, so execution continues to `token.split(" ")`, which throws on `null`. |
